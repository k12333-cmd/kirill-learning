# Чек-лист Pull Request

## Перед тем как открыть PR

- [ ] Я могу объяснить **каждую** строку диффа. Если нет — не открываю, иду разбираться (правило №1).
- [ ] Один PR = одна логическая задача. Если разрослось — режу и предупреждаю Юру.
- [ ] Прогнал агента-ревьюера, красных находок нет.
- [ ] Запустил и проверил руками по критериям приёмки из спеки.
- [ ] Секретов в диффе нет (проверил `git diff` глазами, не только на слово).
- [ ] Отладочные `print` и закомментированный мусор убраны.
- [ ] Коммиты по конвенции: `feat: fix: docs: refactor: chore:` + суть.
- [ ] `README` обновлён, если менялся способ запуска.

## Шаблон описания PR

```markdown
## Что
Одно-два предложения: что этот PR делает.

## Зачем
Какую задачу или критерий приёмки закрывает (ссылка на пункт спеки).

## Как проверял
Конкретные команды и что увидел. Не «протестировал», а что именно запустил и какой получил результат.

## Что осталось / известные ограничения
Честно. Если чего-то не сделал или не проверил — пишу здесь, а не жду, что не заметят.

## Вопросы к ревьюеру
Места, в которых я не уверен и хочу мнение.
```

## После ревью

- [ ] На каждое замечание ответил: исправил / объяснил, почему оставил как есть.
- [ ] «Исправил» без понимания причины — не считается. Если не понял замечание, спрашиваю.
- [ ] После мержа — удалил ветку.
