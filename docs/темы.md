**ДЗ:** без мыши, только командами создать структуру `~/Projects/kirill-learning/{learning-log,src,notes}`, положить в каждую папку по файлу, показать дерево. Скриншот терминала.

**Зачёт:** проходишь весь путь без гугла и подсказок.

## 🔴 A2. VS Code + Claude Code ⏱ 1 ч

Рабочее место. Дальше ты живёшь здесь.

**Изучить:** установка VS Code · открыть **папку** (не файл) как проект · встроенный терминал · расширение Claude Code: установка, вход, запуск в проекте · расширение Python.

**ДЗ:** открыть `kirill-learning` как проект, запустить Claude Code, попросить объяснить структуру папки. Приложи в конспект, что он ответил.

**Зачёт:** поднимаешь среду с нуля сам, не подглядывая в инструкцию.

## 🔴 A3. Python-минимум ⏱ 4 ч

Задача не «выучить Python», а научиться **читать** и править простой код.

**Изучить:** переменные и типы (`str int float bool`) · списки и словари · `if/else` · `for` · функции и `return` · импорт модулей · чтение и запись файла · f-строки.
Источник: docs.python.org/3/tutorial — главы 3–5 и 7, по диагонали, не подряд.

**ДЗ — единственное задание, где Клод запрещён.** Скрипт на 40–60 строк: читает CSV с расходами, считает сумму и среднее по категориям, печатает отчёт. Гуглить и читать документацию можно, спрашивать Клода — нет.

**Зачёт:** написал сам и объясняешь построчно.

## 🔴 A4. Git локально ⏱ 2.5 ч

**Изучить:** зачем нужен контроль версий · `init clone status add commit log diff` · что такое коммит и почему он должен быть маленьким · `.gitignore`.

**ДЗ:** завести репозиторий в `kirill-learning` (`git init` — сам, я это не делал специально), 5+ осмысленных коммитов, добавить `.gitignore`, показать `git log --oneline`.

**Зачёт:** сообщения коммитов человеческие — «что и зачем», а не «fix», «update», «asdf».

## 🔴 A5. GitHub и Pull Request ⏱ 2 ч

Модель, по которой работает вся команда.

**Изучить:** удалённый репозиторий, `push` / `pull` · ветки: `branch`, `checkout` · что такое Pull Request и зачем он, если можно запушить в main · merge-конфликт: почему возникает и как выглядит.
Читать: `numiro-repo/CONTRIBUTING.md`, раздел GitFlow — это наш реальный процесс.

**ДЗ:** создать репозиторий на GitHub, запушить · ветка `feature/hello` → изменение → PR в свой `main` → я ревьюю по-настоящему → правки → мерж. Описание PR — по `docs/PR-чеклист.md`.

**Зачёт:** прошёл цикл сам.

## A6. Как устроен рабочий репозиторий ⏱ 1 ч

# Блок B · Код

## 🔴 B1. Чтение чужого кода ⏱ 2 ч

Главный навык на ближайший год. Ты будешь читать больше, чем писать — и чужое, и то, что нагенерил Клод.

**Изучить:** идти от точки входа · не читать подряд, а искать «где это делается» · поиск по проекту · функция как чёрный ящик «вход → выход», внутрь лезем только если надо.

**Материал:** `transcriber/transcribe.py` из моих проектов — маленький, рабочий, с внешним API.

**ДЗ:** разбор по блокам: что делает каждый, что на входе, что на выходе. Плюс 2 вопроса, ответа на которые в коде не нашёл.

**Зачёт:** нашёл 4 из 5 сам и объясняешь причину — а не «переписал по-другому и заработало».

## B3. Зависимости и виртуальное окружение ⏱ 1 ч

Чтобы понимать, почему «у меня работает, у тебя нет».

**Изучить:** `pip` · `venv`: зачем, как создать и активировать · `requirements.txt` · почему нельзя ставить всё глобально.

**ДЗ:** пересобрать проект в venv с нуля, зафиксировать `requirements.txt`, проверить на чистой папке.

**Зачёт:** я клонирую репозиторий и запускаю по твоему README без вопросов.

**Изучить:** зачем тесты · `assert` · простейший `pytest` · что такое «покрыть крайний случай».
